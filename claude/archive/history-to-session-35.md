## Part 1: The session log as of session 35

Session count: 35.

**Status and order live on the Jello board** (since session 35): the Birb Cube board in the Jello artifact, https://claude.ai/artifact/1HH1kCcnvGa5QSPGNb9S5C. At session start, after this log and the file map, read the board (Claude: `ArtifactData` list of `games/birbcube/cards`). Cards in "Built, needs testing" come first, then the top of "Up next". As work lands, move and tick cards there; this log keeps the history of what each session did.

De-tangling pass: once a week, on Thursday afternoon after the token reset (decided Oct 25, replacing the every-N-sessions rule). Last full pass: session 21 (Oct 29, at 4.91). Next one: Thursday, Nov 5. Rule of thumb from session 21: line count only flags a file to look at; split a file when it does several jobs, not because it's long. Files over 400 lines that each do one job and were left as they are: `Pedestal.cs`, `Hands.cs`, `Radio.cs`, `RadioPlayer.cs`, `Backdrop.cs`, `BirbDesigner.cs`, `BirbAnimator.cs`. Left on purpose: `Hud.cs` and `BucketPanel.cs` (stand-ins to be replaced by in-world controls), and the looks and species parts of `Bird.cs` (Step 15 rewrites them). **First thing next time: `BirdMover.cs`** (about 1,000 since 5.10's thirst trips and far-water flights; its WATER section is a job of its own, so move it into a partial-class file). Also worth a look: `Bird.cs` (about 730 since 5.10; its night, rain and NEEDS parts could become their own file), `GameEngine.cs` (about 680 since 5.03's time keys) if it grows again, and `BirbDesigner.cs` (about 690 since 4.99: its species editor is a job of its own and could become a partial-class file). Newly over 400 (seen in session 33, grown outside logged sessions): `ChatMessages.cs` (about 490) and `HologramRenderer.cs` (about 420).

**Open bugs:** none (see `qa-plan.md` section 6). B2 (rain streaks near the camera drawn as tall, thick columns in the Hologram View) fixed in 5.07 (session 32) and confirmed by you the same day. B1 (starfield drift stutters) closed in session 22.

**Committed:** everything through 5.10 is tested and committed (you confirmed Nov 1, in session 35). What 4.94, 4.95, 5.02, 5.05 and 5.08 changed isn't recorded (most likely small fixes and tweaks made while testing; 5.06 added `SkyOrbs.cs` and `skyorb.fs`, 5.08 `StationFinder.cs`; a card on the board tracks getting them into the file map).

**Tooling: compiling and screenshots in the workspace (session 30).** Use **`tools/ShotDriver/README.md`**; don't write a new driver. Each session: stage the files it lists, copy them to a working folder, `bash tools/setup-workspace.sh` (installs .NET 10, glslang, xvfb, the null sound device, builds the driver), then `bash tools/shot.sh <script.txt> [out folder]`. Scripts are plain text (`power on`, `hour 19.3`, `view hologram`, `yaw 180`, `rain`, `shot name`...); `set`, `call` and `print` reach any member by path. `scripts/tour.txt` is a ready-made look at most of the game and the driver's own smoke test (about 30 s). Building the driver also compile-checks the whole game against your DLLs. Older notes that still hold: for a refactor that should change nothing, build the old code and the new code each with a small test file in place of `Program.cs` that prints the tables both ways, and diff the two printouts (session 26); a headless test can make birds if it opens a hidden raylib window under `xvfb-run` and calls `PartLibrary.Load` first (session 27). With no shell on your computer, files are staged here, edited in a separate working folder, written back with an mtime guard, then staged again and compared byte for byte (session 29). **Added in session 31:** for a before/after look comparison, make one world first and save it, then load that same save into both builds paused (`GameEngine.Paused`; the light still follows the Hour slider while paused), so the shots match bird for bird; the hologram's scan sweep is timed by the real clock, so single shots can still differ by a passing teal band. **Added in session 33:** the driver can make that save itself: a script that ends with `set engine.Saves.autosaveTimer 0` then `frames 3` writes `birbcube-save.json` into `~/birbshot/run`; copy it out and pass it to later runs with `--save`. **Added in session 34:** for behavior stats, drop a throwaway static class into `tools/ShotDriver/` (in the workspace copy only, never written back) and `call` it from a script between `wait` lines (sampling every bird each time, printing a summary at the end); a script of a few hundred lines can be generated with a short Python loop. Three in-game days (45 sim minutes) run in a few minutes. The old `.glb` files in `resources/` and `rocker_click_original.wav` don't need staging.
